# 结果复用与基线校验：修复记录

以下两项问题于 2026-11-19 修复。本页保留触发条件、当前行为与兼容边界，方便检查旧实验。

## 收敛扫描复用了不同参数的旧结果

旧脚本只凭 `summary.json` 是否存在就跳过计算，更换噪声强度、线路、脉冲参数或参考积分节点数后，可能混用旧数据。

现在 `scripts/scan_convergence.sh` 在计算参考解或提交任何作业前进行只读预检：

- 用实际 CLI 参数解析器比较保存配置与本次请求，包含默认参数；逐项检查数值设置，不以目录名代替配置。
- 检查整个 ROOT 中已有扫描组的共同物理参数，包括本次未选中的旧组；各组允许具有不同的层级、步长、键维数及 reset 策略。每个本次选中的组再核对自己的全部计算设置。
- 参考解核对 `NODES` 等设置；即使 `REFERENCE=0`，已有参考解仍须匹配，因为后续 converge 会自动发现它。
- 对 `--layers-json` 和 `--noise-json` 还比较输入内容与保存的快照，避免同一路径文件被修改后复用旧结果。
- 缺少配置字段、配置互相矛盾、未完成运行、损坏的 JSON 或缺少必要结果文件均停止，不会覆盖、删除或静默复用。请等待原运行完成，或换新的 ROOT。进程数、BLAS 线程数和输出位置不作为结果身份。

这是扫描脚本的参数一致性保护，不是源码版本锁定或完整文件内容校验，也不为手工混放结果后单独调用 `compare`／`converge` 提供全局正确性保证。旧结果没有被重算或改写。

## 基线分析未核对线路内容

旧 `heom_spp.analyze --baseline` 只检查 SPP 维度，因此不同门或旋转角的同形状线路可能被拿来比较。

现在每份基线必须提供可解析的 `layers.json`，并与被分析线路匹配：比特数、位序约定、gate-after 约定、层顺序、块边界，以及每个门的类型、作用比特、旋转角和驱动相位。缺失、损坏或不匹配时，在缓解计算前报错并指出基线名称。

允许描述性差异：来源、层名称、Trotter 步编号，以及同一并行块内互不相交门的列举顺序。噪声模型可以不同；该检查不要求噪声参数相同。不同分解即使产生相同总幺正，也不会被自动视为同一分层线路；物理上是否适合作为基线仍需按实验目的判断。

## 回归测试

- `tests/test_reuse.py`：真实小规模输出的匹配复用、参数／节点变化、输入 JSON 原地修改、缺失／损坏记录、未选中旧组，以及实际 Bash 脚本在新计算或 Slurm 提交前拒绝不兼容数据。
- `tests/test_analyze.py`：同形状但不同门、比特、角度、相位、层顺序／块边界的拒绝；缺失元数据的拒绝；同线路不同噪声及描述性差异的接受。
